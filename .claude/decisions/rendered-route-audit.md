# Rendered route ownership audit

On `758a3a4`, A-316 remains **P1**. A departing page's parameter observer can run with the incoming page's parameters. A cold lazy navigation can keep the old page mounted after that run. A-315 remains P1 and the missing boundary-reset signal in A-311 remains P2. The next implementation decision belongs to the router's mounted segment. Preserve the existing reactive scheduler.

## Reachability

The repository archaeologist traced the generated applications, CLI generation code, compiler examples and public router guide. We checked the 87 tracked template and overlay files, six compiler example files and 12 CLI/scaffolder source files. The frontend router starter has two static pages. The full-stack guest book uses a loader and submits through a form event. The router guide documents a lazy parameterized page with a loader, and the public `useParams` example demonstrates an effect performing a read on a changed ID. We found no shipped page or example that automatically persists page state using a route parameter. The navigation and extra observer run are reachable through public APIs. The P0 escalation in the roadmap requires evidence of a silent wrong-destination write on a supported path. The shape of an application that a consumer could write does not establish that outcome for a shipped application. Consumer code outside this checkout was unavailable.

## Observations

The test owner used a retained public layout, named page labels, component construction and cleanup counters, and controlled guard/chunk promises. A separate packed browser fixture sent one constant anonymous event when a leaf mounted or when the operator refreshed the presentation. Its fixed in-memory counter measured those events independently of the parameter observer. Both guard and chunk holds left it at two. It advanced to three when the incoming leaf mounted, and to four on the next eager navigation. There was no route-selected write target or durable storage.

| Navigation on the baseline | Observation |
| --- | --- |
| Query-only or fragment-only | Same layout and leaf nodes. The leaf's parameter observer stayed at one run. |
| Eager sibling, same-pattern remount, or prewarmed lazy sibling | The old leaf's observer ran a second time. On an instantaneous swap its cleanup preceded the new leaf's construction. |
| Asynchronous guard followed by admission | The original observer stayed quiet during the guard wait. It ran again at admission. |
| Cold lazy route | After admission the original page remained visible and alive while its reactive read had moved on. When the module landed the new page replaced it. |
| Named transition | Incoming and outgoing nodes coexisted. The outgoing owner survived until leave completion. A local signal could still update an outgoing subtree during that interval. |
| First-ever loader read during the hold | The departing public page had already loaded its caption. Its first call to the captured bare loader's `data()` during the hold returned the destination caption. The typed handle for the departing route read idle. A last-read snapshot alone has no original value to return in this case. |
| Reused static leaf under a changing parent parameter | Both live leaf instances shared the same route object and the same static leaf path. Their enclosing parent instances differed. Comparing only the leaf's own parameters and route object cannot tell which instance is departing. |

### Why changing flush order fails

An isolated comparison prioritized an already queued effect ancestor before its descendants. It suppressed the extra read on guard admission, yet the eager sibling, same-pattern remount, prewarmed sibling, cold lazy and animated cases still recorded it. It also failed 16 of the 44 existing A-128 tests. For example, a child can perform the update that keeps its owner open, or supply a value that owner must read later in the same flush. Show, Switch and For controls distinguished paint-then-close from close-then-paint. A named Transition continued to observe a cosmetic update in a later flush while leaving. Disposal prediction and sorting within one round cannot supply a still-mounted page with the correct match. [Flush-order tests](../../packages/azerothjs/tests/reactivity/flush-order.spec.ts) and [the binding A-128 decision](../FLUSH-ORDER.md).

### A separate transition defect

With a named route transition, navigate from one single-element layout with a nested leaf to a different single-element layout with its own leaf. Give each leaf a constant label and count constructions. The destination leaf gets constructed twice, once inside the still-leaving layout and once inside its arriving layout. Before leave completion there are three mounted leaf instances. Dispatching the outgoing layout's transition end removes both instances under that layout and leaves the genuine destination. The eager and cold cases both reproduced this in the in-memory renderer and packed Chromium. With transitions off, both cases constructed the destination once. This requires no parameter reader or loader. It is tracked separately as A-335, tracker entry 51, P2. The common segment design must prevent an outlet in a retired ancestor from building new descendants while allowing its existing subtree to finish its animation.

## Decision constraints for the joint design

1. Keep navigation truth and presentation truth explicit. The router already admits a match before its chunk is ready. Each mounted Routes instance derives its own displayed match in `driveRoutes`. A retained layout needs a reactive signal for that instance's rendered selection so a boundary around an outlet can retry once the displayed match changes. A boundary beside the outlet must keep its independent fallback. Specify the behavior before first presentation, on a blocked or missing page, and under nested and multiple Routes instances. [Route driver and slot machinery](../../packages/azerothjs/src/router/routes.ts)
2. A segment's read scope must survive its construction call and reach deferred children, controls and nested outlet placements. Follow the rendered selection while the segment's full position, including its ancestors' identities and bound parameters, still matches. Mark a departing placement permanently retired, including across a rapid return to the same route. A retained layout must still observe a committed descendant change. Preserve the physical ownership of deferred hydration established in unit 8. [Current construction frame](../../packages/azerothjs/src/router/provider.ts) and [route lifecycle](../ROUTER-LIFECYCLE.md).
3. Give an active segment the resource for its own loader key. The current router reuses one resource per level. Retaining that object or reading its last observed value cannot preserve the departing page's outcome. The prototype must handle an unread settled value, loading, refresh, error and refetch with cache enabled and disabled. Distinguish a held page from a permanently retired one. A command from either cannot silently refetch the arriving page's key. Specify promise settlement, lifetime and eviction before selecting storage. [Loader selection](../../packages/azerothjs/src/router/use-loader.ts) and [router loader ownership](../../packages/azerothjs/src/router/router.ts).
4. Preserve the public raw router and its guarded match. Compare implicit and explicit same-router hooks inside a segment, outside a segment, and against a foreign router. Today `useRoute(router)` returns the actual location getter. Explicit `useLoader(router)` chooses the deepest loader while the bare construction form chooses the current level or nearest loading ancestor. Keep selection and lifetime as separate rules. Document how raw URL fields, scoped params and declared query schemas should behave before changing hook behavior. Preserve the query-only no-remount contract and the guarded location snapshots. [Location tests](../../packages/azerothjs/tests/router/use-route.spec.ts) and [public router guide](../../packages/azerothjs/docs/router.md).

The architecture analyst and independent refuter accepted this direction conditionally. The static defensive review found no evidence that warranted elevating the severity. The next step is to prototype the rendered signal and segment-owned loader view with the earliest read occurring after a hold, a retained layout, a nested outlet during leave and rapid return. Compare cache-on and cache-off behavior and have the public hook contract refuted before integration. All four framework items remain open.

## Verification

- **Source and experimental controls.** The unmodified revision passed 217 existing tests across 18 files and 19 disposable route, control-flow and animation comparisons. Two further probes demonstrated ancestor identity and the first unread loader result. A separate role reproduced the nested-outlet issue with both transition settings on eager and cold routes.
- **Packed and native browser checks.** Chromium 151, Firefox 153 and WebKit 26.5 exercised a hard SSR load and ongoing navigation. The registered Playwright agent inspected the displayed controls, timing, console and network. Its 11 GETs returned 200 and four anonymous POSTs returned 204. An early automated Chromium run emitted four terminal abort notices after receiving those 204 acknowledgements. Using a one-byte acknowledgement consumed by the same fixture, all three engines completed the nine stages with 39 GETs and 12 POSTs, all HTTP 200, zero console messages, uncaught exceptions or failed requests. The four independent Chromium transition comparisons used 10 GETs, all HTTP 200. Browser QA verified closure of its isolated browser and all three fixture ports.
- **Repository and packaging.** A clean checkout on Windows with Node 24.22.3 and npm 11.18.0 passed `npm run verify` (436 files, 7,358 passed, two skipped) and `npm run smoke` (15 packages, six executable targets, 627 shipped files). Three registry-backed release checks timed out on the first full run. A direct Vitest diagnostic lacked the npm CLI entry point; the npm-script retry passed 18/19 with one registry timeout. The successful full rerun used four Vitest workers, the original timeouts and npm’s prefer-offline cache setting. All product sources, tests and published APIs were unchanged in this audit.
