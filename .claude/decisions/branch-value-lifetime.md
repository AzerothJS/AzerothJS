# Values retained by conditional branches

## A-210 and A-212

On 86229c0 a compiled reading desk selected Birch after Atlas, then closed and filed the record using its `let=` accessor. An unread binding filed Atlas. Invoking the saved callback after reopening on Cedar returned Cedar. In `driveShow` one narrowed memo lived for the entire Show and updated its last truthy value only when pulled. Its boolean sibling saw Birch even when no binding did. The compiler already passes an accessor to both value callbacks.

## Contract and ownership

Allocate one accessor per truthy showing. While mounted, a read pulls the current condition. Both a Show selection and a live read remember the truthy record they observe. On removal, disposal or failed construction the accessor retains that record by reference. Cleanup can read it without evaluating the condition or subscribing. A batched value that neither selection nor a live reader observed has no effect. Reopening creates another accessor. Independent mounts and reusable Match descriptors share no per-showing state.

Keep the single cached Show condition from A-262. Its truthiness computation supplies the active binding with each observed selection. Match allocates its binding inside its existing render thunk, preserving lazy ordered selection and the manual zero-argument render method. The shared binding owns its narrowed memo. Connect that binding's disposal to the branch owner and release its source and owner references on retirement. Place root acquisition and branch materialization under the existing rollback mechanism, including direct Match callback failure. Preserve the initiating error. Check the outgoing owner's disposed flag before publishing or pulling, including during user cleanup.

Show's constant SSR accessor still uses one sample. Match's existing SSR selection and value sampling remain intact. Fresh client branches and adopted buffered or streamed branches use the same lifetime. There is no new syntax, export, serialization, compiler contract version or migration. Existing thunk rebuilding and Switch priority stay in effect. Each active showing allocates one binding root and one narrowed memo. Dormant cases allocate no binding. The change introduces no new rendering sink or external input.

A shared Show-wide latch cannot isolate escaped callbacks. Polling or a separate scheduled writer can miss an in-batch read. Eager evaluation of every Match would violate short-circuiting. Keeping state on a Match descriptor would couple independent roots. Independent design review also identified failing lazy materialization, reentrant cleanup and direct ownerless Match failure as required rollback cases.

Review of the implementation exposed one additional ownership boundary. A manual `Match.render()` can run directly in an effect or memo. Its per-run cleanups execute in registration order before the owner drains. Prepend a pure freeze callback so earlier user cleanup and siblings can read their own records even when cleanup changes the source. Leave reactive disposal to the owner. A failed manual build removes its entry from the run's cleanup list. Only direct renders inside a running computation incur this list insertion. Normal renderer branches build inside their own roots.
