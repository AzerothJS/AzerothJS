# Evaluating a Show condition that supplies the branch value

## Decision for A-262

At `ca464f8`, a compiled `<Show when={ props.slot } let={ slot }>` constructs the slotted component once on the server and three times in the browser. Passing children through `when={ props.children }` has the same effect. A markup prop is a getter that builds its tree on each read. In `driveShow`, the initial latch, narrowed memo and truthiness memo each evaluate the getter. A single visible component can therefore have two detached peers with active mounts, effects or requests. A-288 already ensures that the visible streamed widget receives its own result.

Use one eagerly sampled, pull-derived value memo in the value-callback path. Its computation owns the work started by evaluating the condition. The existing truthiness and narrowed memos read the same sample. A dirty condition recomputes when a reader needs it, including during a write wave. The truthiness comparison preserves the branch while the condition stays truthy. Disposal or recomputation of the sample releases its owned work through the normal memo lifecycle. Each Show owns its sample and each server rendering evaluates its condition once.

The initial sample is part of synchronous component setup. If it throws, Show must stop before constructing a fallback or continuing the caller. A plain eager memo can report the error to a scoped or global handler and return an uninitialized value. Independent refutation reproduced the resulting spurious fallback. Use the existing memo constructor and its creation-time disposal path, with an internal entry point that rethrows an error from the first computation. Subsequent exceptions use ordinary memo error handling. Preserve public memo behavior, the Show signature, SSR markers and compiler output.

Changing compiler prop getters would change how every component constructs slots. Pushing a value from an effect would allow a branch constructed during a write to see an outdated value. Caching a thrown exception as a value would leave the failed computation registered until its owner disposes. The internal sampling mode uses the existing dependency graph, owner and error-handling machinery. Successful renders add one memo per value-callback Show and avoid repeated execution of the condition. The zero-argument branch driver, including Suspense, and Match keep their existing evaluation rules.

Document the lifetimes of named slots, children and an explicitly derived slot in the component guide and the public Child type. A typed diagnostic for repeated user-authored reads remains a separate tooling proposal. Existing compiled applications receive the runtime fix. Serialization, data encoding, cross-request state and package dependencies are outside the changed path. There is no new wire or public API. A-210 and A-212 own retained accessors and their behavior across showings. A-121 and A-211 own branch selection and cleanup exceptions.

## Acceptance

Count setup, mount and live effects independently from visible DOM. Check zero reads, one placement, two intentional reads, hidden derived content, reactive updates, failure delivery, cleanup and SSR node adoption. On a streamed page the slot and its sibling should show their own data with zero client refetches. Compare the original and corrected packed application in Chromium, Firefox and WebKit and exercise the public controls through registered Playwright MCP. Check the isolated defect reversions, full repository gate and clean package smoke before updating the product records.
