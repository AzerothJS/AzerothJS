# Fetcher tracking and imperative mutation calls

Unit 6, A-206 and A-207. Decision on 2026-11-21 at 54c148e. The canonical execution order places the form gate A-208 after these items. This record refines the implementation and verification rules of the local FETCHER-TRACKING.md dossier.

An effect remains the active subscriber while it calls a resource fetcher, cached fetcher or mutation write. A synchronous signal read adds an incidental graph edge before the first await. Changing that signal can abort an unrelated request, empty an input while Suspense rebuilds its branch, page through a list on mount or send a duplicate write. On the original runtime two unrelated changes caused two extra fetches and aborts and changed the autosave count from one to three. Fourteen functional assertions failed on the unchanged source. Synchronous owner/cleanup and reactive guard controls passed.

## Decision and independent challenge

- Call application fetchers synchronously inside an untracked frame at plain resource start, shared-cache fetch start and direct cache-disabled fetch. An application router loader has its own diagnostic identity inside the private shared router fetcher. Observe each distinct loader even when two routes share the router family. The original fetch result, throw, promise handling, receiver and abort timing stay with the existing caller. Promise assimilation outside the callback keeps its existing entry-point semantics. Reactive source/key reads, refetch ticks, cache version reads and guards retain their real subscribers.
- Wrap the entire imperative mutation run in public untrack. This also covers synchronous cancellation and the invalidation it can trigger. Queued work after an await already executes outside the initiating effect. Explicit dependencies evaluated by the caller as arguments stay tracked.
- In development, a fetch invocation may install a synchronous read observer in the existing tracking-frame slot. A frame is a real subscriber, an observer or null. Nested computations save and restore it. Explicit untrack and neutral cleanup frames suppress attribution. A plain root still inherits the enclosing frame. A nested fetcher owns its own observations. An observer never becomes a producer subscriber, including for selectors, whose key slots exist only for real subscribers.
- Select the ordinary and diagnostic tracking paths once. Production signal, memo and selector reads keep a direct subscriber check with no observer dispatch. Use Vite's build-time development flag when available and the existing runtime DEV fallback for raw modules. A process-less raw ESM host without build-mode metadata retains the existing development default. A production Vite consumer must exclude the observer from its emitted hot path even in a browser with no process global.
- Mark a raw callback in a WeakSet synchronously at its first observed read, then emit the diagnostic in a microtask. Shared raw identities warn once. Use the family label when present and the fetcher name when available. Explicit untrack acknowledges an intentional snapshot. No per-key warning registry or retained application data is needed.

The archaeologist and analyst checked the current call sites and scope. The bug investigator traced the already-aborted mutation path. The independent refuter rejected the earlier dossier's assumption that the runtime DEV flag folds out of a production browser bundle and challenged the selector, loader identity and nested-frame cases. The test engineer specified positive controls for source tracking, synchronous registration, guard reactivity, cancellation and actual emitted browser behavior.

Untracking the whole resource effect would sever the key and refetch dependencies. Deferring a fetch would lose the synchronous abort listener and owner. A fake graph subscriber can allocate selector keys or disturb memo lifetimes. A static diagnostic alone misses imported callbacks. No compiler emission change, new syntax, package or request authority is required. Applications that used an incidental read as a key must move that value into the resource source, cached arguments or route inputs. The README and editor hovers must show the migration.

Acceptance uses source-based Vitest regressions and a packed, compiled SSR and hydration fixture. Check persisted input identity, request and write counts, explicit refetch, load-more, per-identity warnings, nested and neutral frames, and development/production behavior in Chromium, Firefox and WebKit. The registered Playwright QA agent independently exercises real controls. Run the full repository gate, package smoke, and independent review before closing the canonical records.
