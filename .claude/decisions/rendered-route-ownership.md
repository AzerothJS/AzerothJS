# Rendered route ownership

A-315, A-316, A-311 and A-335 share the renderer's distinction between an admitted navigation and a mounted segment. The [baseline audit](rendered-route-audit.md) identified this boundary and ruled out global effect reordering. This decision is prototyped against `f36e53b`.

## Public contract

- `router.location`, `router.match`, `router.loaders` and uses of the existing hooks outside a matching routed segment retain their navigation semantics. Inside a matching segment, `useMatch` and `useParams` follow that segment's displayed selection. `useRoute` keeps live URL, query and history fields and supplies that segment's params. The in-segment getter can therefore differ from `router.location`. Passing the same router explicitly still identifies the same presentation. Passing a different router selects its own global state. Query and declared search inputs continue to follow the URL. Bare `useSearch()` uses its segment's schema. Explicit `useSearch(router)` uses the admitted leaf, and a handle fixes the schema.
- `useRenderedMatch()` returns the ready-to-display match getter for the enclosing Routes instance. A retained layout may capture its current value when building an outlet boundary's fallback and reset when it changes. A guard's decision alone cannot trigger a premature reset during a chunk hold. A missing or blocked route yields null within its fallback. A synchronous observer can see a ready selection before DOM placement. Calling the hook without a matching Routes context is an error.
- A retained segment follows a ready descendant. A completed child placement records that descendant for any later leave. Reading an intermediate selection must never change that history. A segment waiting for a replacement keeps the last displayed selection. Child placements inspect their parent before consulting their own route and params. A slot demotes the old placement before building its replacement. That specific instance remains retired across a return to identical parameters and through its leave animation. A transient selection sampled inside a batch must not retire an instance that never leaves its slot. Ordinary local effects and transitions retain their existing lifetimes.
- Bare `useLoader()` still selects its own or nearest loading ancestor, the explicit router form selects the deepest loader, and a typed handle selects that exact route. Within a segment, each form reads the loader generation belonging to the selected position, parameters and declared search key. A loader that leaves the active key freezes the four displayed fields, including a previous error or an in-progress indicator. Reading a settled field for the first time during a hold returns the same outcome as reading it before navigation.
- Refetch from an active frame with the current loader key drives the normal resource. A call for an obsolete key or retired placement resolves without a request. A queued scoped refetch that loses its key cannot force the arriving key; an outstanding scoped waiter is released at handoff. A direct router-level resource still follows superseding requests. Native `createRouter` provides key-qualified bindings. Structural routers supplying only `loaders` retain their own resources and behavior. Server rendering uses the original resource so the streaming session can identify its fetch.

## Implementation boundaries

A Routes instance latches the displayed match, accepted search and level bindings together, including during deferred hydration. A per-placement owner context carries that selection to effects, delayed children and outlets after construction. Each nested slot builds from its owning placement. Instance-local state supports independently mounted Routes instances and a foreign nested router.

At the existing resource driver's key handoff, copy the outgoing level's latest fields before the driver can overwrite them. Preserve the ordinary fetch, cache, error handling and seed pipeline. Each level needs only its current and upcoming views. A held placement keeps its own reference, so the router needs no historical key registry. Bind scoped demand to the actual source key at drive time.

Reading the current shared resource after a navigation, retaining only its object, or remembering the last value the application happened to read all lose an unread prior outcome. Global scheduler changes cannot protect a page that stays mounted across multiple flushes. Resetting an outlet boundary at guard admission can reconstruct the failing page before its replacement is available.

## Acceptance

Exercise eager, warm, cold, guarded, instant and animated navigation; late first reads with both cache settings; error, loading, refreshing and refetch through supersession; nested and multiple Routes instances; fresh return to a retired route; and a retained outlet-boundary reset. Preserve raw router getters, explicit/typed selection, SSR/hydration seeds, error routing, true not-found/blocked fallbacks and unit 8 adoption. Verify compiled published packages and real browser interactions on the same source. Record any remaining design objections before production integration.

## Verification on Windows

- The independent test owner ran the same 35 public-entry-point tests on `f36e53b` and the corrected implementation. The baseline failed 30 and passed five compatibility controls. The implementation passed all 35, including cache-on and cache-off holds, refetch settlement, retained and retired placements, two independent dispatchers, server rendering and hydration. Reintroducing each of 18 individual faults caused at least one test to fail.
- Independent refutation rejected two earlier prototypes. An outgoing missing-page fallback could start another destination request. Reading a ready intermediate match during a batch could overwrite the retained layout's history before that child mounted. The final design includes the fallback in its matching scope and records descendant history on placement. The cached loader also keeps the destination view idle until the driver publishes that key's fields, including during a synchronous call from the destination fetcher.
- A query-only benchmark originally woke a data observer 52 times. The scoped getters now subscribe per field and compare field values. Across 50 hash changes and 50 query changes, the original runtime and the final implementation each made 102 schema parses and 50 loader calls, with two data observations and one mount. A separate router and scheduler run passed 825 tests. Component constructors that navigated again or replaced the root matched baseline DOM and cleanup results.
- The architecture analyst compared per-placement and router-wide ownership. The independent architecture refuter accepted the corrected implementation with explicit compatibility and timing requirements. The independent code reviewer checked the full source, regression tests and public documentation. Its final addendum approved the compatibility text, fixture cleanup and corrected index encoding, with no outstanding findings.
- `npm run verify` passed the build, lint, type check, publish metadata and all 439 test files on Node 24.22.3 with npm 11.18.0. Vitest reported 7,393 passed and two skipped. One WebSocket interceptor test hit its 15-second timeout on the first full test run. - `npm run smoke` packed and installed all 15 packages into a clean consumer. It imported 134 framework and 43 compiler exports, verified six executable targets and checked 631 shipped files.
- A packed public application passed seven workflows each in Chromium, Firefox and WebKit. During a cold hold, the first read showed the previous caption. The failing outlet reset once when its next route became ready, while the independent sidebar stayed in its fallback. The eager and lazy named transitions each constructed one destination leaf.
