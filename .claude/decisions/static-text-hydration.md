# Static text adoption and hydration fallback reporting

## A-216 and the remainder of A-118

At `dcfee32`, a dispatch form loses a draft typed before startup when its label combines static text with a constant. The same constant alone adopts. The server's `serializeChild` in `reactivity/ssr.ts` flattens arrays, emits no bytes for an empty string, and emits ordinary escaped text for static primitives. The HTML parser can put multiple leaves into one Text node. The static arm of `hydrateChild` in `renderer/h.ts` calls `HydrationCursor.takeText()` once per leaf. The second claim runs past the text, raises a mismatch and sends the whole container through client rendering. Production also suppresses the existing fallback warning. The earlier A-118 nested-anchor correction shipped in `1227e9a`.

## Design

Adopt a contiguous run of static primitives through its cursor. A nonempty static leaf must claim a Text node or continue a static claim at the same position. Prefer a new Text node when one is present so a DOM with explicitly separate text children still adopts. An empty string contributes no serialized text and may consume nothing. It still claims an available Text node, including one created by splitting the served DOM. Arrays and absent children are transparent. Claims of elements, reactive anchors and control-flow ranges cannot lend their text to another run. Keep ordinary cursor claims strict, including native nodes, opaque values and a descriptor that explicitly requests a Text node. Design review reproduced the missing native button that sharing all leaves would silently discard.

Match text structure as the existing single-leaf path does. Comparing or splitting by the length of the client value would reject differing snapshots and parser-normalized line endings, and splitting would mutate the served DOM. Adding serializer separators would change existing markup, require compatible server/client deployments and increase the size of every affected response. Cursor state belongs to one synchronous or deferred range walk. It costs constant space per cursor and requires no DOM writes, getter evaluations or second pass. The renderer handles buffered and streamed markup using the same rules. Raw text, textarea/title and reactive markers retain their own adoption routines. A-295 owns the newline that HTML strips from preformatted elements.

Report a structural fallback at the root or island catch site, once per recovery, through the existing console warning in both development and production. A deferred route mismatch goes through the same root handler. A successful adoption, an abandoned route pass or an ordinary application exception has no fallback to report. A warning identifies the reason, the physical parent element where available, the stopped node (or end of the inspected range) and the recovery action. Describe DOM structure without including attribute values, text contents or arbitrary comment bodies. Generate these strings only on failure. An event or global callback would add a subscription contract to duplicate the existing warning. The change stays within the runtime package. The public API, emitted compiler contract v6 and SSR bytes remain compatible with precompiled components.

## Verification

Compare the original and corrected runtime through compiled markup, parsed server output, hydration and later reactive updates. Check drafts, form and text identity, focus, caret, genuinely missing nodes or markers, independent roots, deferred adoption and island recovery. Use controls for lone and reactive values, real structural mismatches and development/production reporting. Run permanent regression tests against the baseline and targeted faulty variants. Exercise a clean packed form in Chromium, Firefox and WebKit and through the registered Playwright MCP. Run repository verification and package smoke after final review.

## Review and baseline evidence

- At `dcfee32`, 164 existing tests passed in six relevant suites. Compiled forms lost the pre-startup draft for a constant beside static text, a render callback parameter beside text, a lone empty string and nested string arrays. A lone nonempty constant, zero, absent values and a reactive array were passing controls. The permanent tests use both a buffered response and parsed streamed HTML and check node identity and later interaction.
- The packed baseline exercised ten routes in development and production across Chromium, Firefox and WebKit. In 24 valid workflows the cursor replaced the form and erased the draft. In 12 more, a genuine structural mismatch replaced the affected scope without a production warning. The native Chromium check independently observed the draft and selection loss and compared a passing lone constant with a malformed label.
- Review found a valid form with a control named `tagName` could throw while formatting the new warning. A custom element could also supply a getter that threw. The cursor now reads the DOM's element identity when claiming tags and reads the built-in structural properties when describing a mismatch. The getter is resolved at call time so server imports can run without global DOM constructors. A standalone cursor supplied with a DOM in that environment reads the base property below custom overrides. The browser suite exercises both a form used as the hydration container and a form encountered inside another root.
- A separate reentrant root issue surfaced during design review. If root construction synchronously calls `render` on the same host, a later structural mismatch in the superseded root can dispose the newer mount. Public runtime probes reproduced this on the baseline and the candidate. A-337 and [tracker entry 53](../framework-bugs.md) record the follow-up. Deferred routes that lose ownership before loading have their own verified guard.

## Final evidence

- Of 73 new regression cases, 51 failed on the baseline and 22 passed as controls. The corrected files passed all 294 tests in 11 focused suites, both in the workspace and in an independent archive. Every one of 26 deliberately faulty variants failed a permanent assertion. Independent review approved the final diff after six Chromium probes and a seventh check using a standalone cursor in Node without global DOM constructors.
- The packed Kit application ran 72 cases across Chromium 151, Firefox 153 and WebKit 26.5. All 36 valid adoptions preserved the original input, draft, focus and selection. Each of the 36 intentional mismatches produced one scoped warning and a functioning replacement. The streamed route sent the response stream directly over HTTP. The 60 server roots common to both builds matched byte for byte. All 150 final requests returned HTTP 200, with zero uncaught errors or failed requests.
- All 246 installed core distribution files matched the final published-format archive, SHA-256 `8f162fd52e580bcd3c80cd597dafd03b65abe6cbb942bc270063aaaa84a21668`. The app reused the matched v6 compiler. Existing precompiled applications can take this runtime update without rebuilding their components.
- The registered Playwright MCP independently passed 12 final Chromium workflows. Both named-form variants recovered in development and production, and the direct mount retained its form host. A deferred page retained the draft until release and reported the subsequent mismatch once. Every confirmation reached one, all 25 requests returned HTTP 200 and the console recorded zero errors. The three-engine matrix separately collected uncaught page errors. The native browser closed and all fixture listeners were released.
- On Windows with Node 24.22.3 and npm 11.18.0, `npm run verify` passed 7,832 tests in 455 files with two skipped. `npm run smoke` passed all 15 packages, checking 134 core and 43 compiler exports, six executables and 635 shipped files.
