# Reactive declaration tails

## Decision, 2026-11-25

A-169 covers all eight component-body declarations and declarations inside the statement lists and markup expressions the compiler already lowers. At `df4ab2f`, TypeScript accepts both `let open, spare = 2;` and `let open\nmark();`. The slice parser exposes the first declarator, code generation emits that binding and the remaining source disappears. For untyped state the editor copies the whole slice and can even expose the missing binding. Following a `with` object, emission can discard more source in the same way.

The compiler's existing shape diagnostic owns the full consumption check. Compare the first declaration's actual extent with the end of its value and check the bytes after an options object. Keep legal type and initializer syntax, comments, the form brackets and the existing definite assignment spelling. Respect markup and nested framework syntax before trusting a recovered TypeScript extent. Point the error at the discarded source, name the declaration and give the author a repair. Preserve the specific array-suffix and absorbed-declaration findings. Walk declaration, effect and watch options in their component-body expression context.

Malformed `as` and `satisfies` spellings require a statement-list owner and evidence at the operator or its operand. Preserve ordinary casts, ASI-separated statements, type members, imports and expressions containing nested framework constructs. In particular, `state as\nready && mark();` is a legal cast. The same file can run with a global supplied by a host or bundle setting, beyond the source-only compiler's view. Requiring a local binding would change those programs. A declaration named `as` followed by that expression is written `state as;\nready && mark();`. The project-aware editor can diagnose a missing value in the cast.

Teaching each emitter and the editor to discard the same text would conceal the error. Lowering comma lists would add a new grammar and still lose the following statement. Rejecting every recovered initializer or every TypeScript parse error inside a cast would also reject valid markup and framework blocks. Keep existing compiler/runtime contract 7 and the editor's recoverable projection. Valid sources require no migration. Diagnostics quote a bounded excerpt of locally authored source. Limit fallback parsing to candidates so ordinary files avoid a new checker pass.

## Acceptance

Compare baseline and corrected public diagnostics, editor ranges, projection, client and server builds. Cover the historical three operator spellings, valid casts with local and external bindings, nested handlers in options, array-form, generics, comments, comma expressions and a typed draft in the interactive packed inventory control. Run the full repository verification and consumer smoke sequentially after independent implementation review.

## Discriminating evidence

The original A-130 inputs contained a name at the end of the keyword's line followed by `mark();`, a typed list beginning on the next line and a joined index starting with an elision. The independent investigation traced these through the first TypeScript declaration, both emitters and the editor projection. At baseline, the two primary inventory examples built in all three Vite modes. Native Chromium showed zero recorded receipts on either broken page and one on the corrected spelling. All three pages accepted the same stock update while preserving a draft entered before hydration.

The cast compatibility test used identical component bytes, including a type named `ready`. Supplying a global value of `true` ran the following call once. Supplying `false` ran it zero times. Omitting the value produced a reference error. With the matching ambient declaration, the editor resolved the external value. Without it, the editor reported TS2304. Consequently the syntax-only pass cannot make this spelling a build error while preserving working hosted apps.

Review identified two additional requirements. The original operator diagnostic rescanned through the last semicolon for every malformed line. Its range must end at the associated statement, and later errors must have independent ranges. The first implementation also trusted a recovered TypeScript end inside a valid arrow containing a reactive declaration with a multiline conditional type. A working packed baseline rendered `2` and then `7` when the inner initializer changed. Verify both the legal outer initializer and an actual following tail. Two interface members named `state` and `open` on successive lines need to survive both emission and projection, alongside a real split declaration in a function.

The accepted implementation uses statement and successor offsets and a sorted index of parser errors for an operator whose name and grammar are ambiguous. The shared value parser can mask balanced brace interiors when raw TypeScript needs recovery inside a nested framework block. These masks preserve original offsets. The declaration scanner uses affirmative evidence of an interface or type member when the keyword and name span a line break. The compiler reports shape errors before client or server emission. The editor maps the same errors while continuing to offer a virtual file for repairs.
