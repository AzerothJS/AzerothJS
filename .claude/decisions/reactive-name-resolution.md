# Lexical names in the reactive compiler walk

Unit 14 covers A-181, A-215 and A-183 at `5db831b`. The dependency collector and rewriter share a TypeScript AST walk. Generated render callbacks can carry a row getter through the render plan or a compiler-owned row marker. Component analysis already extracts the props parameter name. An identifier in a declaration, label or module clause has a different syntactic role from an expression with the same spelling.

## Baseline and decision

Ordinary arrow parameters already shadowed a row in a simple map after unit 9. A block local, catch binding, loop variable or closure referring to a later local could still receive the outer row's getter call. The walk considered component sources when registering locals but omitted ordinary row names. A component declared with `p` as the parameter also rendered `p.n` as a snapshot. The analyzer looked for the literal name `props`; a client-only attribute happened to update through a separate clone optimization. Finally, a class field named after a state became an invalid method call on the left of `=`. Labels and named exports could likewise receive a call in a position where TypeScript requires a name.

- Resolve reads against the nearest lexical binding. Retain getter treatment for the framework's own row parameters. Ordinary parameters, destructured bindings, block and function locals must shadow enclosing row getters according to JavaScript scope, including delayed reads of declarations that appear later. Preserve array-form field access and diagnostics at their existing owners.
- Thread the authored component receiver into dependency collection and emission. Nested scopes can shadow it just as they can shadow a canonical `props` parameter. Preserve destructured prop aliases, standalone compiler callers and the clone-path behavior of bare references, including imported accessors.
- Leave class field names, labels and module import/export specifiers in their grammar positions. Walk computed names and field initializers as expressions. Refuse a local named value export of module-level `state`, `derived` or `deferred` with a source-located diagnostic. An explicit exported reader function can expose its value. Type-only exports, re-exports from another module, and aliases of ordinary values remain valid. The module's existing semantic gate should enforce the same rule in standalone and Vite compilation.

Treating every row occurrence as a getter breaks local JavaScript. Rejecting ordinary shadowing would disallow valid code, and wrapping every prop in a getter would change callback and object semantics. Exporting the underlying signal accessor by name would give consumers a function while the source-level declaration exposes a value. Keep the changes in the compiler. Existing component mount, subscription and cancellation ownership stay with the v6 runtime. Rebuild components to pick up corrected emitted code. A newly reactive text binding can introduce hydration markers, so exercise adoption and compare served HTML with the client.

## Acceptance

Independent refutation confirmed a block-contained `var` belongs to its enclosing function body, while parameter defaults run outside that body environment. A named class expression binds its name inside the class. Computed method and accessor keys resolve before method parameters enter scope. Detect local export bindings across component-separated module regions and in either declaration order, using actual lowerable constructs and top-level statement ownership. The suggested reader belongs immediately after its reactive declaration in the same opaque region. A-339 tracks a separated module reader that exposes its accessor. A-253 covers writes from component markup.

The same distinction applies to erased TypeScript declarations and enum member names. A generic type parameter does not mask a value expression. An enum initializer can read an outer state or an earlier enum member, according to its scope. Independent testing also caught a candidate that treated a registered array-form record parameter as plain when it happened to shadow the props receiver. The existing form convention also supports helpers called indirectly. Preserve record field access there and let a nearer ordinary local shadow its containing row. Inferring callback types from a list of array method names would lose that indirect case.

Independent code review found four cases before acceptance. An `implements` clause keeps the type name while a class base expression reads its value. Namespace-local declarations, including hoisted variables, have their own scope. A literal computed enum key binds the member for subsequent initializer expressions. Two nested ordinary callbacks receiving records preserve the existing field convention. The corrected callback fixture displays `3/3`, then `5/5`, on the original button in all three rendering modes. TypeScript declarations merged across separate enum or namespace bodies require further name resolution, tracked in A-338.
