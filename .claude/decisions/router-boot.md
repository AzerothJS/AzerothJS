## Decision

- Give the client one authoritative routing verdict. Start with `{ kind: 'pending' }` while there is no initial decision, or the previously supplied valid blocked seed. Publish match, not-found or blocked in one transaction. Preserve the last settled verdict during later waits. A real unmatched URL settles synchronously. A lazy chain with an admitted guard is a match even while its code downloads. Keep raw location, guarded match, and the broader pending indicator available with their distinct meanings. The closed TypeScript union gains one member, requiring an additional branch in exhaustive consumers.
- A guard receives pathname, parameters and search. A change to one of those inputs reevaluates it. A fragment alone does not. Keep structural equality on the public matched chain, synchronous guard signal tracking, and supersession of obsolete continuations. Apply both fulfillment and rejection of an async guard inside a batch. Carry loader search from the accepted location so an unchanged chain does not fetch a new query before its guard admits it. Keep prior loader data and DOM while a verdict is held. A query redirect is a new decision for the new search. A refused redirect remains closed. If a leave blocker prevents the redirect, retain an established view, or settle the initial request as blocked if it has no previous verdict. A stale async redirect must not win over a newer navigation. A redirect that changes no guard input cannot be treated as admission.
- Remember the router's boot pathname, search and expected presentation before running guards. Adopt server nodes only for that URL and the matching initial presentation (including the exact seeded blocked status). A fragment alone has no server identity. A different settled branch starts fresh within the Routes range. Preserve sibling DOM and the retained layout on a navigation raised during a legitimate adoption. A structural router without boot metadata can render fresh. Expose the framework's check as an optional internal router member; preserve the existing handoff wire format. String and stream rendering consume the server's prior verdict and do not run client guards.
- Keep deferred adoption inside the existing Routes instance and its hydration ticket. Recheck the live owner, pass, ticket, boot identity and readiness at the driver. Only framework drivers that own a hydration cursor run their first effect synchronously while claiming that cursor. Reuse the normal effect body, ownership, cleanup, error routing and subsequent scheduling. The original reactive flush queues other writes and public effects in their existing order. If the URL or branch changed, release the ticket and use normal DOM mounting in that range. Preserve focus on first fill.

A generic read of `router.pending()` in the renderer can hide an already settled page while a loader refreshes. A null match cannot distinguish a new router from an actual 404. Matching element tags cannot identify the page that owns the contents. Reopening hydration for every effect created during a pass would extend its authority to unrelated siblings. A nested batch already inside a flush cannot make queued effects execute in the adoption window. A route-local microtask prototype retained the page but made a live sibling build a hydration descriptor instead of DOM when a mount effect wrote a signal. A blanket immediate first run made an explicit application batch observe 0 then 1 instead of just 1. Collecting all new effects into a private queue let a new application observer run before an existing observer that had already been queued. The cursor-specific prototype preserved both public ordering controls, the live sibling and the served nodes.

### Refutation amendments

1. Capture the owner and both route markers’ actual DOM parents at cursor entry. The HTML parser can place a table row and its markers in an implicit tbody while the logical cursor still points at the table. After installing the driver, reserve a ticket before the cursor frame returns only if the range still owes adoption. Releasing a ticket for an already complete sibling could close the pass before a later sibling registers. A user batch can delay the driver's very first run until the original pass has unwound. A ready, synchronous first run still adopts immediately.
2. Treat the adoption walk as one Routes-local operation. Freeze its exact match for all nested slot builders and defer any root-kind change or teardown triggered by component mount until the walk completes. Then reconcile the current kind and segment identities in DOM mode. A navigation during an already legitimate walk can retain the adopted layout. While first fill is waiting, subscribe to changes in readiness even if the presentation kind remains a chain. After first fill, keep ordinary chain-to-chain updates at their established segment granularity.
3. A deferred adoption must still own the same ticket, live pass, owner and region. A disposed or replaced mount cannot clear its replacement or run mismatch recovery against it. Release in a finally block. Dispose rejected partial roots before mounting the fresh answer, including adopted child slots. Route a non-mismatch exception to the original error scope once. A driver that finds a still-cold current route continues to wait under its existing ticket.
4. Capture loader handoff eligibility against the original URL before any synchronous guard redirect. Apply seed values or failures only to the matching level key. A stopped guard redirect must distinguish a declined leave blocker from a navigation that actually committed. A fresh async blocker completion must belong to the current guard run. Hash-only history updates remain cosmetic.

The independent seed check compared twelve benign cases with shared caching on and off. Synchronous admission retained the initial success or failure without a request. After a delayed admission both outcomes initiated a new read, and selecting a different public page in the construction batch skipped its required loader. The resource's first drive consumes an unqualified initial seed, including when its first source is skipped. For seeded route loaders only, bind the seed to the boot level key and the first eligible guarded location. A single internal typed `buildResource` behind both public overloads and the router path hides the initial value or failure until admission, retains it while the first guard waits, applies it synchronously on that key, and discards it on a different key or a terminal nonmatch. Use the existing cache entry, force and settlement logic afterward. Ordinary resource seeds retain their existing skip and refetch semantics. This changes neither the public resource constructor nor the loader wire format.

### Suspense after cold chunk admission

The compiled unseeded case distinguished a cursor from a resource driver. During a flush the cursor consumes the server range before the resource's ordinary first drive reports loading. Delaying the fetch or running resource effects early changes application scheduling. Instead record which Suspense branch SSR emitted. Adopt that branch once, then let the normal scheduler reconcile actual loading. Only the first adoption enters the matching seed scope. The stream runtime records the exact numeric markers it swapped in a WeakSet. Client adoption claims the marker so that a later chunk cannot remove live controls. The fallback and ready branches of that numbered boundary use their respective seed scopes during the first walk. Older ambiguous markers retain loading-based inference. An independent refutation required a distinction between an unswapped shell and an already swapped legacy boundary, an owner-bound release even for constant resources, and an equality barrier to keep a still-pending fallback. An empty inline stream boundary always renders children and keeps its existing bare marker.
