# Optimistic cache reads and mutation outcomes

Design review for A-324, A-325 and A-326, 2026-11-21. These entries share the M3 mutation follow-on scheduled immediately after unit 5. The principal engineer owns runtime integration.

## Failure and ownership

At the unit-5 implementation, `create-resource.ts` mirrors layers even when the shared entry has never received a value. `data-cache.ts` calls projections directly on reads and removes a confirmed layer before calling it during a fold. A projection can consequently throw from a version notification, escape the optimistic declaration before the write, interrupt a successful multi-entry landing, or interrupt fetch settlement before waiter resolution and parent renewal. Moving the version wake later would still leave the displayed data wrong. The fresh branch of `readValue` also exposes pending guesses that its fetch-join branch omits.

A gated reproduction from the unmodified source sent zero writes on two clicks. Both promises rejected, the mutation error stayed empty, and the cart displayed 7 after fetching and revalidating a server count of 5. With a fetched base and a pending write, the fresh direct call returned 1 and the joined call returned 0 while the resource displayed 1.

## Decision

- The cache entry owns its base and ordered layers. A resource with no base stays loading while fetching, or exposes its fetch error. No projection, including a constant update, creates a base. A fetched `undefined` is a real base when `hasValue` is true.
- Resource reads try the layers in call order. A projection that throws leaves its input visible and subsequent projections receive that input. A pending layer stays eligible on a different base. A development diagnostic identifies the family and reports the original exception once per layer. Only the application projection invocation is guarded.
- Landing still supersedes an older in-flight fetch. A confirmed layer over an absent base waits for the first qualifying fetch. On a real base the fold preserves order. A confirmed layer that throws during the fold is removed and marks its entry for authoritative reconciliation at its landing, including when explicit invalidation is empty. Preserve the unit-5 drop contract, partial-fold freshness and the other entries in the same run. A hydrated seed cannot establish whether a retained confirmed write is included. Such an entry needs reconciliation even when ordinary clean seeds skip a fetch.
- Mutation results describe the write. A refused write keeps its own failure, cancellation withdraws only its own layers, and an accepted write reports success. A bad declaration or invalid patch target remains an application error that rejects before sending. A declaration that fails after naming an earlier target must install no guesses.
- A direct cached call returns the committed cache base on a hit or a join. A loader can store this value safely on either path. For optimistic presentation use a subscribed resource. The committed base includes successfully folded writes and can be fresher than the last fetch. The prior fast path could expose pending changes, so this is an observable compatibility correction.
- A direct reader that arrives after invalidation asks for a settle begun at or after its observed mark. A reader that began earlier keeps its original lower bound. At zero subscribers the invalidation itself remains mark-only. A later direct reader can require a follow-up. An abandoned direct reader rejects with its signal reason and removes its own demand. Other subscribers, readers, revalidation and teardown keep their ownership rules.

## Alternatives and verification

The repository archaeologist and architecture analyst independently confirmed the queue and the existing owner. The registered bug investigator traced the distinction between declaring a patch and invoking its projection in source. The separate Vitest reproduction provided the execution evidence above. The test engineer identified the existing drop, partial-fold freshness and branch-disposal pins. The architecture refuters challenged retaining a failed fold on a fetched base, waking a marked reader with an ambiguous seed, and mistaking a genuine observer error for a failed write.

- A fetched fold that refuses its input removes exactly that layer and marks at its landing. A cold landing also marks for reconciliation. A seed adopted while confirmed cold layers remain is provisional. Keep a qualifying fetch and its waiters, or start one for an audience. Serve the seed to mounted resources while refreshing. The first authoritative success retires confirmed layers it includes. A seed alone can temporarily understate or overstate the accepted writes. An ordinary seed keeps its original adoption rules. The independent seed-versus-mark case without any mutation belongs to A-327.
- Fetch settlement must release eligible waiters and arrange required follow-up and parent renewal even if notification raises an unrelated application error. Finish mutation-owned batched state transitions and route escaped observer errors separately from the server result. Preserve observable exceptions, the declarative misuse rejection, and the ordinary synchronous error behavior of user-owned batches.
- A pre-aborted one-shot call rejects before starting work. A live one-shot with no remaining audience relinquishes its fetch. A second reader keeps the shared fetch alive. An ordinary cache reset or teardown keeps its existing settlement behavior. A subscribed resource is the migration for direct-call clients that used the published optimistic fast path. Record the change in the unreleased changelog for release classification under VERSIONING.md. A folded base can differ from the server when callers suppress invalidation on noncommuting writes.
- The old held-rethrow test relied on a constant projection turning a never-resolving fetch into data. Exercise its disposal/error assertion on a seeded or fetched resource undergoing an actual refresh. Give cold loading and first-settlement semantics their own gated tests.

A seed over confirmed cold layers reuses a qualifying GET already in flight. With a subscriber or held reader and no GET, adoption starts one immediately. With neither, the entry stays stale until a reader arrives. Mark-bound readers remain pending at adoption. A failed qualifying GET rejects a direct reader with the fetch error, sets the resource error alongside the provisional data, and leaves recovery to the next read or explicit refetch. These rules apply to the shared adoption seam used by resources and router seeds, including explicit empty invalidation. Router loader entries are private and cannot be targeted by a public mutation patch. A first seed without a confirmed cold layer retains the existing waiter semantics, tracked separately in A-327.

Projection diagnostics are delivered outside the state transition. A throwing diagnostic sink is observable independently. An escaping fetch observer error is reported after the cache schedules follow-up and parent renewal and resolves eligible waiters. A mutation flush that fails after its transitions complete reports the observer failure through the asynchronous error path. The accepted receipt or refused server error remains available to the caller.

The fast-path optimistic behavior was present in the tagged 2.1.0 runtime. A release that changes a published behavioral guarantee follows the major-release rule in VERSIONING.md. The unreleased changelog documents the direct-read migration. Compiler output and the emitted helper contract are unaffected.

Synthesizing an empty object cannot establish the fetched type. Catching around an entire notification or mutation would hide unrelated failures and misreport accepted writes. Resolving the waiters early would leave a stale UI. Projecting all direct reads can bake an optimistic value into a separate loader cache after rollback. Inferring which asynchronous caller owns a read would need context propagation across user awaits. The existing entry, sequence clock, waiter list and scoped cache can implement the decision without a second registry.

The changes are in the runtime and its documentation. There is no new package, compiler construct, serialization format or public signature. Server request scope, hydration ownership, cache teardown and the existing post-write generation checks continue to apply. The projections are application callbacks operating on shared data, and must remain pure. Ordinary reads without layers stay constant time. Layered reads retain their existing linear traversal. The change introduces no new network destination, trust boundary or persisted input.

Acceptance requires gated tests for cold success and rollback, a later real base, nullable and falsy data, multi-entry landing, seed reconciliation, partial declaration, fresh and joined direct calls, loader rollback, marked and aborted waiters, and a fetched projection failure during a refetch. Preserve the held-error branch test with a real source of data. Check a packed compiled cart's DOM, loading and error states, server writes, console, request outcomes and hydration through the named Playwright QA role. Run the full repository gate and packed smoke, and obtain independent diff review.

## Acceptance, 2026-11-21

The final browser captured 26 network entries. Twenty-four returned HTTP 200 and two cold GETs were cancelled as their writes superseded them. All 11 requests in the fetched-cart scenario returned HTTP 200. The production console recorded zero messages, warnings or errors. The human approved navigation and clicks for the final session and a one-time close. Both loopback fixture ports were released.

The two permanent Vitest suites add 20 cases. Six initial mutation regressions failed against the original source, including zero POSTs and false failure receipts. Seven initial direct-read cases failed and the existing committed-fold control passed. Independent negative controls removed seed preservation or settlement bookkeeping in disposable copies. The seed cases woke too early and the direct dependency failed to renew. Final testing also caught two cancellation races. Last-reader abort now releases demand before a same-task mutation landing. An abort that precedes synchronous same-key seed adoption rejects the caller with its original reason and leaves the seed available to other readers.

The native architecture refuter accepted the amended design. Independent registered code review covered the actual runtime diff and the final reentrant correction. Node 24.22.3 and npm 11.18.0 passed `npm run verify` on an isolated checkout with byte-matched candidate sources and tests. All 430 files passed, with 7,181 tests passing and two skipped. The gate includes the build, ESLint, both type checks, package lint and the full Vitest suite. `npm run smoke` installed the 15 packed workspaces, checked six executable targets and inspected 621 published files.

The registered Playwright QA role exercised the original and final packed applications in isolated Chromium on Windows. The original showed 7 after two clicks and a refresh with zero writes and 5 on the server. The final cart stayed loading while reads were gated, showed two successful receipts, and settled at 7 after explicit refresh. A fetched cart whose projection refused its base retained 5 while the write was pending, then reconciled at 6 with one accepted write. Both pages hydrated the existing server root. The final app's installed framework JavaScript matched the local archives. The final core archive SHA-256 was `7e3fd7cf5ed5fa1870984f25d6f51828b33762b33fa19da8e57c286527ae204f`. The shared-cache behavior has deterministic native regression coverage and packed-browser integration evidence. There was no new compiler, platform-specific API or security boundary to qualify.
