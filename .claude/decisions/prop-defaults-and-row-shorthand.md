# Object shorthand and destructured prop defaults

Unit 14 continues at `f697a37` with A-164 and A-171. The preceding lexical binding fix already distinguishes a framework row getter from an ordinary local. This unit changes how the compiler emits the resolved read.

## Decision

The rewrite currently emits `use({ item() })` for a shorthand row property. Use one identifier-read edit for reactive sources, rows and destructured props. Keep the authored property key, comments and identifier spelling. A shorthand named `__proto__` creates an own data property; its explicit equivalent uses a computed string key. The normal property, getter call, form field and write paths retain their existing ownership.

A prop fallback is lazy, uses nullish semantics, and can run again on each read. On the baseline, a no-argument arrow and a logical fallback fail to parse. A supplied value is lost with a literal conditional. The existing unit 9 lexical capture protects names from the component body but leaves a sibling prop unbound. Preserve the original TypeScript pattern in tooling. In the compiler, group each fallback as one operand, assemble the complete prop alias map, then use the shared lexical rewriter on each captured initializer in parameter scope. Give name-bearing defaults a reusable per-component thunk so chains and diamonds do not duplicate initializer bodies in the generated module. Preserve updates through getters and evaluate only the selected fallback. Ordinary assignment in an initializer still follows JavaScript evaluation order.

Nested object bindings use their enclosing property's fallback before reading the leaf. Defaults can read renamed and nested aliases, and a closure can capture a later parameter. An immediate read of a self or later binding is in its temporal dead zone. Keep the generated props receiver and helper names clear of authored bindings, including escaped spellings. A module binding named `props` can be read by a destructured component.

Refutation added three requirements. A function-valued sibling used as a bare callee receives the same receiver as an ordinary local function. A pattern containing a forward reference records the earliest active initializer and restores it in `finally`. A sibling reader checks its declaration order before accessing the property. This also handles an earlier closure invoked by another default, including when the caller supplied the later value. Backward-only patterns require no such guard. Report an assignment to a sibling prop alias in a default at the target. Shadowed local assignments, writes to module variables and changes to members of an ordinary object keep their normal behavior.

The editor and CLI share the hygienic receiver. The projection copies the readonly destructuring pattern with its source map and puts the component body in a child function scope. Its `var` and function declarations therefore cannot capture a name in the parameter default. The callable declaration still accepts the same optional typed bag and returns the same element type. The separate named-parameter projection error under A-340 predates this correction.

Destructuring eagerly at setup would lose reactivity and change side-effect timing. Recursively substituting initializer text duplicates code and fails on cycles. Altering the parser or runtime would move JavaScript expression semantics away from their existing compiler owner. Runtime contract v6, render ownership, escaping, subscription cleanup, streaming and cancellation continue through the same APIs. There are no new dependencies, asynchronous operations or public syntax.

## Acceptance

Compare compiled row objects to their explicit equivalents in client, universal and development output. Exercise row/index bindings, scopes, form rows, component/render callbacks, host bindings and handlers. Parse and run paired SSR, hydration and client results. For defaults, check omission, explicit overrides, nullish and falsy values, calls, reactive updates, lexical capture, default grouping and chained dependencies. Run counterexamples against the baseline and deliberately faulty changes. Verify the packaged compiler through Vite development, production, SSR, and independent Playwright MCP before the full repository and package gates. The next scheduled unit is A-234 and A-237.
